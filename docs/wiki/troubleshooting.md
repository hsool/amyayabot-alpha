# Troubleshooting

문제 해결은 **증상 → 가장 흔한 원인 → 확인 방법 → 해결 방법** 순서로 진행하세요. 한 번에 여러 설정을 바꾸면 원인 추적이 어려워집니다.

## 설정 페이지가 열리지 않음

| 확인 | 해결 |
| --- | --- |
| 백엔드가 실행 중인가? | Windows는 루트의 `AmyayaBot.cmd`, Linux/macOS는 `launchers/unix/start.sh`를 다시 실행합니다. |
| 포트가 맞는가? | 설정 페이지 기본 주소는 `http://localhost:18300/settings`입니다. 개발 서버는 `http://localhost:18200/settings`일 수 있습니다. |
| 빌드 파일이 있는가? | 배포 모드는 `frontend/dist/index.html`이 있어야 정적 페이지를 제공합니다. |

## OBS에 오버레이가 보이지 않음

1. OBS에서 **Browser Source**를 추가했는지 확인합니다.
2. URL이 맞는지 확인합니다.
   - 캐릭터/말풍선: `http://localhost:18300/overlay`
   - 투표/추첨/룰렛: `http://localhost:18300/overlay/interactive`
   - 신청곡: `http://localhost:18300/overlay/music`
3. Width/Height를 방송 캔버스에 맞춥니다. 보통 1920×1080부터 시작합니다.
4. OBS 소스 우클릭 → 새로고침을 실행합니다.
5. 투명 배경이 필요하면 브라우저 소스 배경색/사용자 CSS 설정을 확인합니다.

## AI가 반응하지 않음

| 원인 | 확인/해결 |
| --- | --- |
| Gemini API 키 없음 | 설정 > 연결/API에서 Gemini 키를 저장합니다. |
| 출력 채널 꺼짐 | 말풍선/TTS/채팅 출력 중 최소 하나를 켭니다. |
| 채팅 버퍼 대기 중 | 일반 채팅 반응은 즉시가 아니라 버퍼 주기 후 나올 수 있습니다. |
| 필터에 걸림 | 금칙어, 정치/성적/욕설 필터, 사용자 제외 목록을 확인합니다. |
| 중복 방지/쿨다운 | 반응 간격, 반복 방지 설정을 낮춰 테스트합니다. |

## CHZZK 연결이 실패함

1. Client ID/Secret이 비어 있지 않은지 확인합니다.
2. CHZZK 개발자 센터에 등록한 Redirect URI가 로컬 콜백 주소와 맞는지 확인합니다.
   - 이 프로젝트의 로컬 OAuth 콜백 포트는 `18301`을 사용합니다.
3. 설정 페이지에서 인증 URL을 열고 스트리머 계정으로 승인합니다.
4. 승인 후 상태가 connected로 바뀌지 않으면 백엔드 로그에서 OAuth 에러를 확인합니다.
5. 채널 ID는 OAuth 이후 자동 획득되는 흐름을 우선 사용합니다. 수동 입력값과 충돌하지 않도록 주의하세요.

## OBS WebSocket 연결이 실패함

1. OBS를 실행합니다.
2. OBS 메뉴에서 WebSocket Server 설정을 열고 서버가 켜져 있는지 확인합니다.
3. 포트와 비밀번호를 AmyayaBot 설정과 맞춥니다. 일반적으로 OBS WebSocket 기본 포트는 `4455`입니다.
4. 저장 후 AmyayaBot의 OBS 연결을 다시 적용합니다.
5. 장면/소스 목록이 비어 있으면 OBS가 꺼져 있거나 WebSocket 인증이 실패한 상태입니다.

## TTS 소리가 안 남

| 확인 | 해결 |
| --- | --- |
| TTS 출력이 켜져 있는가? | 반응/출력 설정에서 TTS 사용을 켭니다. |
| 브라우저 소스 음소거 | OBS 오디오 믹서에서 Browser Source가 음소거되어 있지 않은지 확인합니다. |
| 엔진 키/음성 ID | Supertone/Fish는 API 키와 voice/reference ID가 필요합니다. |
| 브라우저 자동재생 | OBS Browser Source에서는 보통 자동재생이 가능하지만, 브라우저 단독 테스트에서는 사용자 클릭이 필요할 수 있습니다. |

## STT가 말을 인식하지 못함

1. STT가 enabled인지 확인합니다.
2. 올바른 마이크 장치가 선택되었는지 확인합니다.
3. VAD threshold가 너무 높으면 음성을 침묵으로 판단할 수 있습니다.
4. SenseVoice를 쓰는 경우 모델 경로 또는 다운로드 상태를 확인합니다.
5. CPU 환경에서는 큰 모델보다 작은 모델로 먼저 테스트합니다.

## Vision 테스트가 실패함

| 원인 | 해결 |
| --- | --- |
| OBS 미연결 | OBS WebSocket 연결을 먼저 확인합니다. |
| 캡처 대상 없음 | 장면/소스 이름이 실제 OBS 목록과 일치하는지 확인합니다. |
| ROI 설정 오류 | 수동 ROI 편집기에서 관심 영역을 다시 잡습니다. |
| 게임/해상도 변경 | 기준 프로필과 현재 해상도·UI 배치가 다르면 재학습/재검증이 필요합니다. |
| 비용/지연 | Vision은 캡처와 분석 비용이 있으므로 테스트 주기를 너무 짧게 잡지 않습니다. |

## 신청곡이 검색되지 않음

1. 검색어가 너무 짧거나 애매하지 않은지 확인합니다.
2. YouTube 접근이 가능한 네트워크인지 확인합니다.
3. yt-dlp 관련 오류가 있으면 패키지를 업데이트합니다.
4. 신청곡 오버레이는 `/overlay/music` Browser Source가 필요합니다.

## 팬카페 글 검색이 기대와 다름

| 증상 | 확인/해결 |
| --- | --- |
| 팬카페 결과가 아예 없음 | **연결 설정 → 웹/팬카페 검색**에서 `웹/팬카페 검색`이 켜져 있고, 숫자 `cafeId`/`clubid`가 저장되어 있는지 확인합니다. 숫자 ID 경로는 Naver Client ID/Secret이 없어도 동작합니다. |
| 다른 카페 글이 섞임 | 숫자 `cafeId` 대신 팬카페 이름/URL slug를 넣으면 공식 검색 결과를 후처리 필터링합니다. 정확도가 중요하면 `https://cafe.naver.com/ca-fe/cafes/{id}` 또는 숫자 ID를 입력하세요. |
| “조회수 많은 글” 결과가 전체 인기글과 다름 | 현재 구현은 최근 공개글 몇 페이지를 가져와 `readCount`로 로컬 정렬합니다. 네이버 카페 전체 기간 인기글 랭킹을 보장하지 않습니다. |
| 특정 게시판/비공개 글이 안 나옴 | 비로그인 공개글 목록 기준이라 멤버 전용/비공개/검색 비허용 글은 가져오지 못합니다. 전체 게시판 구조도 public 경로에서 안정적으로 확인되지 않습니다. |
| 갑자기 동작하지 않음 | 숫자 ID 경로는 네이버 웹에서 관찰한 비공식 API에 의존합니다. 네이버 응답 구조나 접근 정책이 바뀌면 재확인이 필요합니다. |

## 장기기억을 초기화하고 싶음

설정 UI의 관리 기능 또는 개발자용 API `DELETE /api/memory`를 사용합니다. 초기화는 되돌리기 어려우므로 방송 로그/요약을 보존해야 한다면 먼저 백업하세요.
